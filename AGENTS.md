- 💬 general
  - use often emojis 🐱
  - write in plain english for non-natives
  - put temporary files (drafts, PR bodies, commit messages, scratch output) inside `temp/` at the repo root
- 🌳 git handling
  - https://conventionalbranch.org
  - https://www.conventionalcommits.org/en/v1.0.0
    - set a scope if it fits
  - commit msg should have a max length of 72 chars
  - PR titles: <conventionalcommit msg> (<ISSUE_ID>)
- 🛠️ task runner handling (taskfile, justfile, makefile)
  - keep them compact and minimal
  - have one-liner recipes as good as possible: `<RECIPE>: <CMD>`
  - use intuitive recipe names, if it calls a cmd `xyz`, then name it kinda like `xyz`.
- 🧪 test handling
  - testing pyramid: unit > integration > e2e
    - unit: each test deals with one function, IO should be mocked.
    - integration: each test deals with one function with real IO.
    - e2e: each test runs the app via public entrypoints, as a user would.
- 📝 docs handling
  - a new CHANGELOG entry should be placed on top of the list if there is any.
  - every non-test function in `src/` needs a `///` docstring directly above `fn` (no blank line)
    - say what it does, what it returns, and when it errors or panics
